# V0

Purpose: prove donor-known transfer works on real external repos.

## Goal

Take a pinned donor module or small donor path and materialize a local host-fit version without preserving a donor dependency edge.

## Success criteria

- operator points at `repo + ref + path`
- `mgt` transfers required local code into host
- output fits host intent well enough to pass targeted verification
- provenance recorded
- donor dependency edge removed
- works on external repos/modules, not only `mgt` itself

## Scope in

- donor-known transfer
- pinned source: repo, ref, path
- modes: `copy`, `adapt`, `synthesize`
- verification: typecheck, tests, lint where available
- provenance / lock metadata
- donor dependency graph walk for immediate required transfer set
- user/agent intent capture as primary constraint input

## Scope out

- open-ended donor discovery/search
- robust donor/host intent critique
- automated donor monitoring
- self-pruning / self-hosting loops
- autonomous repeated repair loops beyond tight bounded retry

## Command surface

```text
mgt add <repo> --ref <sha> --path <module> --to <dst> --mode copy|adapt|synthesize
mgt verify <dst>
mgt refresh <dst>
mgt diff <dst>
```

## Modes

### `copy`

- no model rewrite
- copy donor files / required local set
- baseline and control mode

### `adapt`

- light rewrite for host fit
- preferred likely v0 default for real use
- preserve behavior; prune obvious unnecessary deps

### `synthesize`

- semantic rebuild from donor context
- explicit high-variance mode
- not default

## Dependency policy

- aggressively minimize runtime/library deps introduced by transfer
- never preserve donor repo/package as a dependency edge
- allow local support code when needed:
  - shims
  - bundled helpers
  - framework glue
  - fixtures for verification

## Provenance

Each transfer should retain lineage, likely in lock/manifest form:

- donor repo
- pinned ref
- donor path
- mode
- generation time
- verification state

## Validation

Required:

- compile/typecheck if available
- targeted tests
- lint where practical

Nice to have:

- donor fixture equivalence tests
- bounded retry with compiler/test feedback

## Why external-first

Self-hosting too early gives false confidence.

- too easy to overfit to own repo shape
- too easy to unconsciously design around known internals
- no control group

V0 should prove transfer works against external donor modules first.

## Self-hosting path

Self-hosting starts after external proof.

Proposed path:

1. prove v0 on external repos/modules
2. use `mgt` on internal helper modules inside `mgt`
3. only later use `mgt` to prune `mgt`'s own dependency graph
4. keep external regression corpus as control, so self-hosting does not become self-delusion

## Open questions

- should `adapt` or `copy` be the default mode?
- where should transferred modules live by default?
- how much dependency graph walking is enough for v0 before scope blows out?
